# StoryBook Manager

Десктопное приложение для управления проектами сказок, созданными с помощью storybook_pipeline.

## 🚀 Основные возможности

- **Управление проектами**: Просмотр, создание, удаление и backup проектов сказок
- **Структурированное редактирование JSON**: Удобные формы для редактирования всех типов данных проекта
- **Просмотр медиа**: Встроенный просмотрщик изображений и видео файлов
- **Интеграция с pipeline**: Запуск полного workflow или отдельных этапов генерации
- **Валидация данных**: Проверка согласованности и корректности данных проекта
- **Система backup**: Автоматическое создание резервных копий при изменениях

## 📋 Требования

- Python 3.9+
- tkinter (встроен в Python)
- Доступ к корневой директории проекта MultiAgent

## 🔧 Установка

1. Убедитесь, что вы находитесь в корневой директории проекта MultiAgent:
```bash
cd /path/to/MultiAgent
```

2. Установите зависимости для StoryBook Manager:
```bash
pip install -r StoryBookManager/requirements.txt
```

3. Запустите приложение:
```bash
python StoryBookManager/main.py
```

## 🎬 Вкладка «Болванка» (3D-референс)

«Болванка» — черновой 3D-рендер шота (простые серые фигуры вместо готовой
картинки), который строится в Blender до генерации финального изображения и
видео. Он нужен, чтобы задать композицию, ракурс камеры и непрерывность
движения между соседними кадрами ещё до того, как потрачен хотя бы один
платный вызов генератора изображений или видео.

### Что показывает вкладка

- **Дерево сцен и шотов** проекта с признаком цепочки (`link_type`) и
  статусом каждого шота (готов / устарел / не отрендерен).
- **Сравнение четырёх изображений** шота: начальный и конечный кадр болванки
  рядом с начальным и конечным финальным изображением.
- **Два независимых видеоплеера**: опорный ролик болванки (`blockout_ref.mp4`)
  и финальное видео (`video_final_XX_YY.mp4`) шота — их можно смотреть и
  останавливать по отдельности, у каждого свои кнопки.
- Кнопки **«Перерисовать болванку шота»**, **«Перерисовать цепочку»**,
  **«Пересобрать сцену»** и **«Перегенерировать выбранные шоты»**.

### Предупреждения (не останавливают прогон, но требуют внимания)

Предупреждения попадают в журнал выполнения и в отчёт
`93_blockout/report.json`. Прогон продолжается, но результат стоит проверить
глазами.

- **P01 — использована заглушка.** В сцене не нашлось нужного 3D-объекта
  (персонажа, реквизита), и на его место подставлена условная геометрическая
  фигура (человекоподобная для двуногих, четвероногая для зверей). Список
  заглушек виден в отчёте и на вкладке «Редактор» (`asset_map.json`) — оттуда
  объект можно заменить на подходящий из библиотеки.
- **P10 — рассогласовано.** Изображение шота (начальное или конечное) старше,
  чем время последнего рендера его болванки — то есть болванку перерисовали,
  а картинку ещё нет. Вкладка помечает такой шот «рассогласован», пока
  оператор не подтвердит расхождение кнопкой «Оставить как есть» или не
  перегенерирует изображение заново.
- **P13 — размер болванки не согласован с видеомоделью.** Разрешение, в
  котором отрендерена болванка, не совпало с тем, что просит видеомодель для
  этого шота. Причина всегда указана рядом (`reason`): `aspect_mismatch` —
  модель не подтвердила такое соотношение сторон; `no_size_fields` — у модели
  вообще нет данных о размерах, рендер идёт по общей настройке
  `blockout_resolution`; `chain_size_mismatch` — у шотов одной цепочки разные
  размеры, взят размер первого; `shot_size_missing` — у первого шота цепочки
  не указаны `width`/`height`. Само предупреждение не останавливает рендер, но
  в случае `chain_size_mismatch` означает, что видео-референс для
  несовпавшего шота подан не будет.
- **P17 — справочная строка (не предупреждение).** Показывает сумму
  рассчитанных длительностей всех шотов рядом с ориентиром `screenplay_time`,
  который задал человек. Ничего не блокирует и ничего не предлагает
  исправить — попасть в ориентир на фиксированном наборе длительностей
  (например, 5/7/10 секунд) почти никогда не получается, и это нормально.

### Блокирующие ошибки (останавливают прогон)

- **B01 — длительность не нормализована.** У шота нет `duration_s` из
  допустимого набора значений, либо (после ручной правки длительности прямо
  на вкладке «Болванка») сцена не пересобрана, и то, что зашито в 3D-сцене,
  больше не совпадает с текущей длительностью шота. Лечится повторным
  прогоном генерации шотов либо кнопкой «Пересобрать сцену».
- **B12 — Blender недоступен.** Не найден исполняемый файл Blender, либо его
  версия ниже минимально требуемой 4.2. На панели проверки готовности при
  выключенной болванке это лишь предупреждение, но при включённой болванке и
  реальном рендере — блокирующая ошибка: без Blender строить 3D-сцену и
  рендерить кадры нечем.
- **B15 — не получен набор допустимых длительностей.** Не удалось узнать у
  видеомодели, какие длительности шотов она поддерживает (ни через сетевой
  каталог, ни через встроенный реестр, ни из кэша прошлого прогона). Блокирует
  прогон только при включённой болванке (`generate_blockout: true`) — при
  выключенной болванке вместо ошибки будет предупреждение P14, а
  нормализация длительностей просто не выполнится.

```json
{
  "projects_directory": "plots/storybooks",
  "backup_directory": "StoryBookManager/backups", 
  "auto_save_interval": 30,
  "max_backup_files": 10,
  "json_editor_mode": "structured",
  "window_geometry": "1200x800"
}
```

## 📝 Типы редактируемых файлов

### 1. Brief (00_brief.json)
Техническое задание сказки:
- Название и описание
- Целевая аудитория
- Главные персонажи и локации
- Параметры генерации

### 2. Story (20_story/story.json)
Текст сказки:
- Заголовок книги
- Страницы с заголовками и текстом
- Счетчик слов на странице

### 3. Characters (20_bible/characters.json)
Персонажи сказки:
- Основные атрибуты (имя, возраст, роль)
- Неизменные черты (внешность, пропорции)
- Переменные атрибуты (одежда, аксессуары)
- Референсы изображений

### 4. Locations (20_bible/locations.json)
Локации сказки:
- Название и описание
- Ключевые объекты
- Атмосфера и освещение
- Цветовая палитра

### 5. Shots (97_shots/shots.json)
Видеокадры для анимации:
- Параметры сцен и кадров
- Промпты для генерации
- Технические параметры
- Пути к результирующим файлам

## 🔍 Валидация данных

Приложение включает систему валидации:

- **JSON Schema валидация** для проверки структуры данных
- **Согласованность между файлами** (персонажи в brief должны быть в characters)
- **Бизнес-правила** (количество слов на странице, длительность кадров)
- **Предложения по улучшению** контента

## 🔄 Интеграция с Workflow

StoryBook Manager интегрируется с существующим `workflow.enhanced_engine`:

- Использует `EnhancedWorkflowEngine` для запуска pipeline
- Интегрируется с `custom_tools.storybook.*` для селективной генерации
- Поддерживает мониторинг прогресса выполнения
- Сохраняет логи выполнения

```
├── 90_md/                     # Markdown версия
├── 91_screenplay/             # Сценарий для видео
├── 95_pdf/                    # PDF книги

```

## 🚀 Быстрый старт

1. Запустите приложение из корневой директории MultiAgent
2. На вкладке "Проекты" выберите существующий проект (например, "ryaba")
3. Перейдите на вкладку "Редактор" для редактирования JSON файлов
4. Используйте вкладку "Медиа" для просмотра изображений и видео
5. Вкладка "Генерация" позволяет запускать pipeline и регенерировать контент

## 🔧 Разработка

Для разработки и расширения функциональности:

1. Основная логика находится в модулях `core/`
2. GUI компоненты в `gui/`
3. Конфигурация и схемы в `config/`
4. Утилиты в `utils/`

### Добавление нового типа файла для редактирования:

1. Добавьте JSON схему в `config/schemas.py`
2. Расширьте `core/file_manager.py` для работы с новым типом
3. Добавьте форму редактирования в `gui/editor_panel.py`
4. Обновите валидацию в `utils/json_validator.py`
