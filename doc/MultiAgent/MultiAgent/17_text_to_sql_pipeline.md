# Глава 17: Typed Text-to-SQL

Text-to-SQL в проекте имеет один путь: Typed-пайплайн. Старой маршрут из
NLU-, schema-linking-, generator- и verifier-агентов больше не участвует в
Text-to-SQL.

Источник истины —
[`workflow_pipelines/text_to_sql_pipeline.yaml`](../../../workflow_pipelines/text_to_sql_pipeline.yaml).

## Входы

| Имя | Назначение |
|---|---|
| `query` | Вопрос пользователя. |
| `dsn` | Подключение к базе, переданное доверенным сервисом. |
| `schema_scope` | Разрешённая область схемы. |
| `max_rows` | Максимальное число строк в ответе. |
| `dry_run_only` | Построить SQL, но не выполнять его. |
| `run_id`, `session_id` | Идентификаторы запуска и сессии. |

Выбора режима, legacy-маршрута или отключения исследования схемы нет.

## Три шага

1. `schema_research` запускает Typed research loop — цикл исследования схемы и
   данных. Агент сам решает, какие таблицы, колонки, связи и значения
   ещё нужно проверить. Число шагов заранее не фиксируется; его ограничивают
   общий дедлайн (предел времени) и бюджеты.
2. `sql_solving` запусает Typed solver loop — цикл построения SQL. Каждый
   кандидат проходит типизированные проверки. Если не хватает фактов, solver
   возвращает точный запрос на дополнительное исследование.
3. `db_audit` проверяет свежесть схемы, безопасность SQL и его соответствие
   найденным фактам, затем выполняет его и формирует итог.

```mermaid
flowchart LR
    Q[Вопрос] --> R[Typed schema research loop]
    R --> S[Typed SQL solver loop]
    S --> A[Проверка и выполнение]
    S -- не хватает фактов --> R
    A --> O[Ответ]
```

## Почему цикл не заменён жёсткой цепочкой

Схема базы не всегда описывает смысл данных. Например, тип объекта может
храниться значениями в строках одной колонки. Чтобы понять такую вертикальную
типизацию, агенту нужно исследовать содержимое таблицы. Поэтому порядок этапов
фиксирован, а число исследовательских шагов внутри этапа — нет.

## Запуск

Внешний путь один: AG-UI action `presets.text_to_sql.generate`. Выбирать другой
workflow или другой движок нельзя. Обычный general-purpose manager (менеджер задач общего
назначения) Text-to-SQL не выполняет; он направляет такой запрос в Typed-сервис.

Правила бенчмарков описаны в
[`docs/operations/text2sql-benchmark-protocol.md`](../../../docs/operations/text2sql-benchmark-protocol.md).
